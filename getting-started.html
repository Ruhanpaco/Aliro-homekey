01 · HARDWARE

Start with a simple bench.

You do not need a finished door. A development board and a safe output such as an LED are enough to validate the firmware before connecting a real lock.

ESP32

ESP32-WROOM-32

The current validated development target. Other ESP32 families are supported by the underlying Aliro SDK, but do not assume every board is hardware-tested here.

NFC

PN532 frontend

The NFC frontend sits between the phone and the ESP32. The ESP32 itself does not contain an NFC radio.

OUTPUT

LED before lock

Use an LED or other harmless indicator while testing access decisions. A real relay or strike should come only after the firmware path is understood.

02 · FLASH

Use a trusted tool.

For a released Aliro HomeKey image, the project's browser flasher is convenient because it is served from this GitHub Pages project and uses Web Serial. For a generic ESP32 binary, Espressif's own ESP Launchpad and esptool are the safest general-purpose choices.

03 · FIRST BOOT

The reader should become boring.

POWER

Boot the ESP32

Connect USB and watch the serial monitor. The firmware initializes NVS first, then starts the reader before network administration services.

NETWORK

Join the setup AP

If no Wi-Fi credentials exist, the device starts an Aliro-Setup-XXXX access point and exposes the configuration UI at 192.168.4.1.

CONFIG

Configure hardware

Set the NFC frontend, bus and pins, lock output and polarity. Configuration is persisted in NVS and a restart applies the changes.

VALIDATE

Run the first test

Follow the boot and transaction checks in the first-test guide. Keep a real lock disconnected until the full path is understood.

Security note: a development identity is not a production credential. Aliro HomeKey is an experimental open-source project and is not a certified commercial access-control product.
