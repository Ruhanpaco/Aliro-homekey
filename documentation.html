02 · INSTALLATION

Build from source

The firmware is developed with Espressif's ESP-IDF toolchain.

git clone https://github.com/Ruhanpaco/Aliro-homekey.git
cd Aliro-homekey
idf.py set-target esp32
idf.py menuconfig
idf.py build

Use the project's repository documentation for version-specific configuration and build requirements.

03 · FLASHING

Put firmware on the ESP32

You can flash from the terminal with ESP-IDF, or use the Aliro HomeKey browser flasher for supported release images.

idf.py -p PORT flash monitor

04 · HOW IT WORKS

Transaction architecture

The reader is divided into physical NFC transport, credential/protocol processing and access-control output.

Phone / credential
      ↓
PN532 NFC transport
      ↓
ISO 14443-4 / APDUs
      ↓
esp_aliro_lib + Aliro reader logic
      ↓
credential authentication / validation
      ↓
access-control decision
      ↓
Matter Door Lock or configured GPIO

07 · TROUBLESHOOTING

Common first-test failures

The browser sees the USB device but cannot connect

The serial interface can be present while the ESP32 is not in ROM download mode. Hold BOOT, press and release EN/RESET, then retry the connection. Check the board's USB-UART wiring if automatic reset does not work.

The firmware flashes but the reader does not behave correctly

Capture the serial monitor output, verify the selected target and configuration, and confirm the PN532 wiring and power before changing application-level settings.

A transaction reaches NFC but access does not complete

Separate the transaction into NFC transport, credential processing and lock-control stages. The architecture and first-test pages explain what each stage should report.

08 · DEVELOPMENT

Work with the project

Aliro HomeKey is an active open-source engineering project. Read the architecture before modifying protocol or credential code, keep hardware assumptions explicit, and validate changes on real hardware where applicable.
