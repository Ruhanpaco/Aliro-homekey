Aliro HomeKey

An open-source door reader for Aliro — the Connectivity Standards Alliance standard that Apple, Google and Samsung wallets all implement. Build the reader once, and any compliant wallet can carry a key for it.

Flash it from your browser View on GitHub
v0.1 — beta, and honest about it.

The firmware compiles for ESP32 and ESP32-S3 and boots into a configuration UI, but there is no NFC chip driver yet, so it cannot read a card or complete an Aliro transaction. It has also never been run on hardware. Flash it on a bench, not on a door.

The idea

Putting a key in a phone used to mean picking one vendor's stack — Apple Home Key for iPhones, something else for Android. Aliro is the common protocol underneath all of them.

 Apple Wallet   Google Wallet   Samsung Wallet   other Aliro wallets
        └───────────────┴───────┬───────┴────────────────┘
                                │  Aliro (one protocol, all of them)
                                ▼
                        ESP32 Aliro Reader     ← this project
                                │
                                ▼
                         Access / Lock

What's in it

Aliro transactions

Built on Espressif's prebuilt esp_aliro_lib: reader lifecycle, session loop, expedited phase, and credential lookup by Aliro key slot.

Configure without rebuilding

NFC chip, bus, every pin, lock output, Wi-Fi and MQTT live in NVS and are edited in the browser. Pins wired to flash are never offered.

Web console on the device

Info, MQTT, Actions, Misc and Logs pages, served by the ESP32 itself with no bundler and no CDN.

Setup access point

A board with no credentials still comes up reachable, with a captive portal at 192.168.4.1.

MQTT & Home Assistant

Retained lock state, per-tap events, unlock commands, and discovery so the lock appears without YAML. Off by default.

Serial debug console

status, nfc, unlock, wifi and more at 115200 baud — works with no network at all, which is how a fresh board arrives.

Flash it

Connect an ESP32 over USB and install the firmware straight from this page. Nothing to download, nothing to install.

  1. Plug the board in over USB. It needs 4 MB of flash — an ESP32-WROOM-32 DevKitC or an ESP32-S3 DevKit.
  2. Press Connect and pick the serial port. On a first install, choose Erase device when offered.
  3. When it finishes, the reader starts a Wi-Fi network called Aliro-Setup-XXXX, password aliro1234. Join it and the configuration page opens.
This browser can't talk to serial ports. Use Chrome or Edge on a desktop — Safari and Firefox don't implement Web Serial. Serial access needs a secure connection (https).

Prefer the command line? Grab esp32.firmware.factory.bin from the releases page and write it at offset 0:

esptool.py --chip esp32 --port /dev/ttyUSB0 --baud 460800 \
  write_flash 0x0 esp32.firmware.factory.bin
FileOffsetWhat it is
<target>.firmware.factory.bin0x0 Everything — bootloader, partition table, OTA data and app — padded to the full flash. Use this.
<target>.firmware.bin0x20000 The application alone, for a faster reflash once a board is already set up.

After it boots

Open a serial monitor at 115200 baud and press Enter for a prompt. The console works before Wi-Fi exists, which is the point.

aliro> status     device, network, reader and MQTT state
aliro> nfc        NFC wiring, and what the driver situation is
aliro> unlock     drive the lock output now (GPIO 2 = on-board LED)
aliro> wifi MyNetwork hunter2
aliro> restart

unlock lighting the on-board LED for three seconds is the first end-to-end proof that configuration, access control and the GPIO output all work together.

Known limitations

  • No NFC driver. The transport is a stub that never detects a device. This is the single biggest missing piece.
  • No authentication on the web UI. Anyone on the network can reconfigure the reader.
  • Credential provisioning is unsolved. How a real wallet comes to hold a credential for this reader is an ecosystem process the SDK does not cover.
  • Never run on hardware. Booting, Wi-Fi and the lock output are all expected to work and none have been observed.

Built on espressif/esp-aliro. Structure, GPIO tables and UI style adapted from HomeKey-ESP32 (MIT), with kormax/aliro as the protocol reference. Apache-2.0.
