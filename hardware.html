02 / HARDWARE

What runs it, and how sure we are.

Board support here comes in three honest tiers: hardware-tested, built-and-released-but-untested, and SDK-supported-but-no-board-work. Which tier a target is in matters more than whether it's listed at all.

BOARD SUPPORT

Three tiers, not one list.

hardware-tested

ESP32-WROOM-32

The primary development and transaction-testing platform. Commissioned into Apple Home, ran real Aliro transactions, drove a lock output — everything under Overview was verified on this exact board with a PN532 over SPI.

builds and releases, not hardware-verified

ESP32-C3 · ESP32-S3

CI builds and publishes firmware for both on every release, and both pass the OTA-slot-fit check. Pin defaults exist in boards/ and components/app_config/Kconfig. Neither has been flashed to real hardware by this project — treat as unverified until someone confirms a tap actually opens a lock.

SDK-supported, no board work here

ESP32-C6 · ESP32-H2 · ESP32-P4

Espressif's Aliro SDK targets these chips, so this project could extend to them, but no dedicated release build, partition tuning, or testing exists in this repository yet for any of them.

ESP32 board

WROOM-32 or another supported target. USB for flashing and monitoring.

PN532 module

SPI (default) or I²C, over 4-6 wires. See wiring pins below.

Access output

A relay, electric strike, lock controller, or an LED for bench testing.

Power

3.3V logic only for the PN532 — do not feed it 5V.

DEFAULT WIRING

PN532 over SPI, ESP32-WROOM-32.

First-boot defaults — every pin is remappable from the web UI without a rebuild, and the device refuses wiring that doesn't exist on the target or is already assigned elsewhere.
