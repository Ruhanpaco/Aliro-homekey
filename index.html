WHAT IT IS

A reader, not a vendor silo.

Aliro provides the common access protocol. The ESP32 supplies the embedded platform. This project supplies the glue: NFC transport, credential storage, access policy, lock output, provisioning, configuration and integrations.

LATEST ENGINEERING WORK

The project is moving at the protocol layer, not just the UI.

Recent work has focused on making the reader behave like a real embedded system: keeping WebSocket connections alive, handling malformed frames safely, updating live metrics, publishing lock attributes correctly and tightening the handshake implementation.

Web interface · latestLive connections now actually detect dead sockets.

Client pings now expect replies, stale sockets close into the reconnect path, and live metrics update in place instead of sitting in the console.

Matter · latestAutoRelockTime now matches the hardware.

The Door Lock attribute is exposed and writes are routed through access control, so the reported value and the GPIO behaviour agree.

Aliro · latestHandshake registration was corrected.

The WebSocket post-handshake callback exists on the supported ESP-IDF versions, so the project no longer documents a false API limitation.

Security boundaryUnknowns stay labelled as unknowns.

Wallet compatibility, certification and production deployment are kept separate from what has actually been verified on the bench.
